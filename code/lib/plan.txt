## 23.2 NEW: Master Relay Necessary Start Bound

The current Master has almost no relay awareness:
`gap_count` / `relay occupancy` are just surrogate preferences, not hard constraints.

Step7 already computed:

```python
min_transport_start_s
```

For each gap g:

```
L_g^relay = min_{r in R_g} L_gr
```

For occurrence o:

```
L_o^relay = max_{g in G_o} L_g^relay
```

Add to Master:

```
s_o >= L_o^relay  (enforced only when x_o == 1)
```

i.e.:

```python
model.Add(
    start >= relay_start_lb
).OnlyEnforceIf(x)
```

The Master does NOT perform full relay scheduling,
but MUST include relay feasibility boundaries.

---

## 23.3 NEW: Occurrence Relay-Window Presolve

After `prepare_q3_problem()` or before `build_master()`, compute:

```python
relay_lb[o]
```

If:

```text
relay_lb[o] > latest_start[o]
```

then this occurrence can never satisfy comm requirements.

Disable it:

```python
x[o] == 0
```

Do not let CP-SAT search it.
This is more effective than increasing solver time.
