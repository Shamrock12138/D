# Q4 运输侧预计算说明

本文件对应 COMM 运输快照下的临时计算，不代表 Q3 联合调度已可行，也不代表 Q4 最终方案。现有 Q3 两架中继调度尚未得到可行确认，因此中继无人机、能源组件、通信保障关系及最终综合资源缺口均不在此阶段定稿。

## 计算范围

`Q4_capture_comm.py` 从当前 COMM 候选池保存通过 80 箱和运输资源检查的运输快照。该预览运行时不在 COMM 主问题中加入中继容量近似约束；快照的运输可行性由原有独立运输检查确认，且不能推出中继可行性。`Q4_precompute.py` 核对快照哈希后，按多站架次合并不可拆服务区块，精确枚举 K=2/3 的无标号分区，计算六类运输资源的独立组配置、运输侧冗余和库存缺口，以及组间运输作业时长 CV。

输出仅写入 `code/data/q4_precompute_comm/`：`preview.json` 记录来源、块、分区数及代表方案；`blocks.csv` 和 `transport_groups.csv` 便于查看服务区与运输资源；`validation.json` 记录独立复算。输出状态固定为 `PROVISIONAL_TRANSPORT_ONLY`。若 COMM 重跑后运输架次或时刻不同，必须重新运行预计算，不沿用先前分区数值。

运输无人机占用使用保存的 `flight_release_s`，共享电池占用使用 `battery_release_s`，两者均沿用运输模型已计入的资源释放时刻；工作量使用架次 `end_time_s−start_time_s`。这可以避免把资源周转间隔误认为设备已可复用。

Q3 两架中继得到正式可行解并完成最终冻结后，运行 `Q4.py` 读取 `code/data/q3_final_frozen/`，重新构造包含中继依赖的不可拆块，重新枚举并核算八类资源。运输侧预览方案只用于提前检查框架和讨论权衡，不直接晋升为正式 Q4 结果。
